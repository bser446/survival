# คู่มือเอาตัวรอด (survival)

เว็บแอปออฟไลน์สำหรับใช้ในครอบครัว รวมคู่มือรับมือภัยพิบัติ 15 แบบ ปฐมพยาบาล 32 เรื่อง และเช็กลิสต์ของสำรอง
ปรับเนื้อหาตามที่อยู่ 3 แบบ: คอนโดสูง บ้านสองชั้น/ทาวน์เฮาส์ และบ้านชั้นเดียว

- **คู่มือ (แสดงเด่น):** น้ำท่วม พายุ ไฟไหม้ คลื่นความร้อน ฝุ่น PM2.5 ไฟดับวงกว้าง โรคระบาด แผ่นดินไหว
- **คู่มือ (ภัยอื่น ๆ กดดูเพิ่ม):** ภัยแล้ง/น้ำประปาไม่ไหล ดินถล่ม/น้ำป่า สารเคมีรั่ว เหตุรุนแรงในที่สาธารณะ สึนามิ รังสี/นิวเคลียร์ สงคราม
- **ปฐมพยาบาล:** `data/firstaid.json` 32 เรื่องใน 5 กลุ่ม เข้าจากหน้าแรกและแท็บฉุกเฉิน
- **โครงคู่มือ:** แต่ละเล่มแบ่งเป็น ขณะเกิดเหตุ / เตรียมก่อน / หลังเกิดเหตุ / ห้ามทำ / ตัดสินใจและที่มา
- **เช็กลิสต์:** 3 ชุด (กระเป๋าฉุกเฉิน ของสำรองในบ้าน ติดรถ/ที่ทำงาน) คำนวณปริมาณตามจำนวนคนและจำนวนวัน บันทึกวันหมดอายุ เพิ่มรายการเองได้
- **ฉุกเฉิน:** เบอร์โทรฉุกเฉินและแผนครอบครัว
- ข้อมูลของผู้ใช้เก็บใน `localStorage` ของเครื่องเท่านั้น ไม่มีเซิร์ฟเวอร์ ส่งออก/นำเข้าเป็นไฟล์ JSON ได้

## โครงสร้าง

| ที่ | คืออะไร |
|---|---|
| `data/guides/*.json` | คู่มือรายภัย ข้อปฏิบัติแต่ละข้ออ้าง `src` ไปยัง `sources` ในไฟล์เดียวกัน (`src: []` = ความรู้ทั่วไป ยังไม่ผูกแหล่ง) |
| `data/firstaid.json` | ปฐมพยาบาล: `topics[]` (id, title, group, signs, call, steps, dont) ทุกขั้นตอนอ้าง `src` |
| `data/checklist.json` | รายการของ หมวด และสูตรคำนวณ |
| `data/research/town-additions.json` | ข้อเฉพาะบ้านสองชั้นที่รวมเข้าคู่มือเดิม 8 เล่มแล้ว (เก็บไว้เป็นบันทึกที่มา) |
| `data/research/supplies.json` | ตัวเลขอ้างอิง (น้ำ อาหาร ยา) ที่ใช้ตั้งสูตร |
| `src/app.html` | ตัวแอป (HTML/CSS/JS ไฟล์เดียว ไม่มี dependency) |
| `build.py` | รวม data เข้า `src/app.html` → `index.html` และสร้าง `sw.js`, `manifest.webmanifest`, ไอคอน |
| `index.html`, `sw.js` | ผลลัพธ์ที่ build แล้ว **ห้ามแก้ตรง ๆ** ให้แก้ที่ `src/` หรือ `data/` แล้ว build ใหม่ |
| `sync/` | บริการซิงก์ (Cloudflare Worker + D1): `src/index.js`, `schema.sql`, `wrangler.toml` |
| `tests/` | `ui.test.mjs` (ทุกหน้าจอ ปุ่มหลัก การ escape) และ `sync.test.mjs` (2 เครื่องจำลองกับบริการซิงก์ในเครื่อง) |
| `ref/` | เอกสารอ้างอิง (ไม่อยู่ใน git) |

## Build และทดสอบ

```
python -X utf8 build.py
python -m http.server 8765 --bind 127.0.0.1   # แล้วเปิด http://127.0.0.1:8765/
```

`build.py` เตือนถ้าไฟล์คู่มืออ่านไม่ได้ ขาดฟิลด์ หรืออ้าง `src` ที่ไม่มีใน `sources`

ตัวเลือกของ `build.py`:
- `--no-sync` ปิดการแชร์บ้านทั้งหมด (สวิตช์ฉุกเฉิน ถ้าบริการซิงก์มีปัญหา)
- `--dev` อนุญาตให้แอปคุยกับบริการซิงก์ที่รันในเครื่อง **ห้ามใช้ขึ้นเว็บจริง**

## ทดสอบ

```
python -X utf8 build.py --dev
node tests/ui.test.mjs

# ทดสอบซิงก์กับบริการจริง (สร้างบ้านทดสอบ 1 หลังแล้วลบทิ้ง): build แบบปกติ แล้ว
SYNC_URL=https://survival-sync.thundererz.com node tests/sync.test.mjs

# ทดสอบซิงก์ในเครื่อง: เปิดบริการก่อน (อีกหน้าต่าง)
cd sync && npx wrangler d1 execute survival-sync --local --file=schema.sql
cd sync && npx wrangler dev --local --port 8787 --ip 127.0.0.1
node tests/sync.test.mjs
```

ทดสอบเสร็จต้อง build ใหม่แบบไม่มี `--dev` ก่อน commit

## บ้านและการแชร์

- ข้อมูลเก็บเป็น "บ้าน" หลายหลังใน `localStorage` (`survival.v2`) แต่ละบ้านเป็น field แบบ `key -> [ค่า, เวลาแก้]` รวมข้อมูลจากหลายเครื่องแบบข้อไหนแก้ทีหลังชนะ
- บ้านที่แชร์มีรหัสลับ 32 ไบต์อยู่ในลิงก์เชิญ (`#join=...`) จากรหัสนี้แตกเป็น id ของบ้าน โทเคน และกุญแจ AES-GCM ด้วย HKDF
- เซิร์ฟเวอร์ได้รับแค่ id โทเคน และข้อมูลที่เข้ารหัสแล้ว จึงอ่านเนื้อหาไม่ได้ และกู้ให้ไม่ได้ถ้ารหัสหาย
- บริการซิงก์: `GET/PUT/DELETE /v1/h/<id>` ต้องมีโทเคน เขียนแบบตรวจเวอร์ชัน (409 เมื่อชนกัน) จำกัดขนาด ความถี่ และจำนวนบ้านใหม่ต่อ IP ต่อวัน ลบบ้านที่ไม่มีใครเปิดเกิน 12 เดือน

## ใช้งานออฟไลน์

- เปิด https://survival.thundererz.com/ ครั้งแรกตอนมีเน็ต (GitHub Pages ผูกโดเมนผ่าน Cloudflare DNS) แล้ว "เพิ่มไปยังหน้าจอโฮม" จากนั้นเปิดได้โดยไม่มีเน็ต
- ไม่มีเน็ตเลย: ส่ง `index.html` ไฟล์เดียวไปเปิดในเบราว์เซอร์ได้ (ข้อมูลทั้งหมดฝังอยู่ในไฟล์)

## ข้อจำกัดของเนื้อหา

เนื้อหารวบรวมจากหน่วยงานไทยและต่างประเทศ ใช้เตรียมตัวในครอบครัว ไม่แทนคำสั่งเจ้าหน้าที่หรือคำแนะนำแพทย์
คำแนะนำของหน่วยงานไทยหลายข้ออ้างผ่านข่าวที่รายงานต่อ ไม่ใช่เว็บหน่วยงานโดยตรง

## Deploy บริการซิงก์

```
cd sync
npx wrangler deploy                                                  # ต้อง wrangler login ก่อน
npx wrangler d1 execute survival-sync --remote --file=schema.sql      # เมื่อแก้ schema
```

- Worker `survival-sync` ที่ https://survival-sync.thundererz.com (custom domain บนโซน thundererz.com) ฐานข้อมูล D1 `survival-sync`
- deploy Worker ก่อนเสมอ แล้วจึง push แอปที่ต้องใช้ความสามารถใหม่ของ Worker

- ปั๊มหัวใจเด็กและทารก: เพิ่มหมายเหตุว่าคนที่อบรมแบบเริ่มด้วยกดหน้าอกให้ทำตามที่ฝึกมา

### 2026-10-06 — ภัยใหม่ 7 เล่ม ปฐมพยาบาล และบ้านสองชั้น/ทาวน์เฮาส์
- **คู่มือใหม่ 7 เล่ม** (รวม 15): คลื่นความร้อน/ลมแดด, ภัยแล้ง/น้ำประปาไม่ไหล, ดินถล่ม/น้ำป่าไหลหลาก, สึนามิ, สารเคมีรั่ว/โรงงานระเบิด, รังสี/นิวเคลียร์, เหตุรุนแรงในที่สาธารณะ
- **หน้าแรกแบ่ง 2 ชั้น:** ภัยที่ครัวเรือนไทยเจอบ่อยกว่า 8 เล่มแสดงเด่น ที่เหลือ 7 เล่มอยู่ใต้ "ภัยอื่น ๆ ที่เกิดได้น้อยกว่า" (กำหนดที่ `PRIMARY` ใน `src/app.html`)
- **ปฐมพยาบาล 32 เรื่อง:** ปั๊มหัวใจผู้ใหญ่/เด็ก/ทารก, เครื่อง AED, สำลัก, จมน้ำ, เลือดออก, กระดูกหัก, แผลไหม้, ไฟดูด, ลมแดด, หลอดเลือดสมอง, หัวใจขาดเลือด, ชัก, แพ้รุนแรง, งูกัด, สัตว์กัด, แมงกะพรุน ฯลฯ ยึดแนวทาง ERC 2025 / AHA 2025 (ผ่านบทสรุป) / St John Ambulance / NHS / WHO และหน่วยงานไทย
- **ที่อยู่แบบที่ 3 "บ้านสองชั้น/ทาวน์เฮาส์":** `ctx` ของรายการเป็นค่าเดียวหรือ array ได้ (`"town"`, `["house","town"]`); เพิ่มข้อเฉพาะ 49 ข้อในคู่มือเดิม 8 เล่ม และติดป้ายข้อของบ้านชั้นเดียวที่ใช้ร่วมกันได้อีก 49 ข้อ
- **แก้คู่มือเดิม:** ไฟไหม้ "ห้ามหนีขึ้นดาดฟ้า" จำกัดเฉพาะคอนโด และเพิ่มเกณฑ์ตัดสินใจของบ้านสองชั้น; น้ำท่วม ตัดตัวเลขความกว้างแม่น้ำสายที่แหล่งไม่ตรงกัน
- **เช็กลิสต์:** เปอร์เซ็นต์ความพร้อมนับเฉพาะรายการหลักและที่เพิ่มเอง ของเสริมรายภัยมีตัวนับแยกตามหมวด
- **ข้อควรรู้ของเนื้อหา:** หน้าเว็บ AHA, กาชาด, CDC และ สพฉ. เปิดอ่านตรง ๆ ไม่ได้ จึงอ้างผ่านบทสรุปและข่าวที่อ้างหน่วยงาน; การเริ่มปั๊มหัวใจเด็กและกรณีจมน้ำยึด ERC (เป่า 5 ครั้งก่อน) ซึ่งต่างจากการสอนแบบ AHA ที่ใช้ในไทย (กดหน้าอกก่อน) ควรให้ผู้มีใบอนุญาตทางการแพทย์ทวนก่อนเผยแพร่วงกว้าง

### 2026-10-06 — เสริมความปลอดภัยบริการซิงก์

### 2026-10-06 — เปิดการแชร์บ้านกับคนในบ้าน
- deploy บริการซิงก์ขึ้น Cloudflare (Worker + D1) และ build แอปแบบเปิดการแชร์ ทดสอบสองเครื่องจำลองกับบริการจริงผ่าน
- ชุดทดสอบรับ `SYNC_URL` เพื่อทดสอบกับบริการจริง
- **ค้าง:** ตารางลบบ้านที่ถูกทิ้งอัตโนมัติ (cron) ยังตั้งไม่ได้ เพราะบัญชี Cloudflare ยังไม่มี workers.dev subdomain ต้องเปิดหน้า Workers ในแดชบอร์ดหนึ่งครั้งแล้วรัน `npx wrangler triggers deploy`

### 2026-10-06 — หลายบ้าน และเตรียมการแชร์บ้าน
- **หลายบ้านในเครื่องเดียว:** เพิ่ม สลับ ตั้งชื่อ และลบบ้านได้ที่หน้าตั้งค่า เช็กลิสต์ วันหมดอายุ จำนวนคน และแผนครอบครัวแยกกันรายบ้าน ข้อมูลเดิม (`survival.v1`) ถูกย้ายเข้าบ้านแรกอัตโนมัติ
- **โครงข้อมูลใหม่:** ทุกค่ามีเวลาแก้กำกับ เพื่อรวมข้อมูลจากหลายเครื่อง ไฟล์สำรองรุ่นเก่ายังนำเข้าได้
- **การแชร์บ้านกับคนในบ้าน (ยังปิดอยู่บนเว็บจริง):** โค้ดฝั่งแอป บริการซิงก์ใน `sync/` ลิงก์เชิญพร้อม QR และหน้ายืนยันก่อนเข้าร่วม เสร็จและทดสอบในเครื่องแล้ว เว็บจริง build ด้วย `--no-sync` จนกว่าจะ deploy บริการซิงก์ขึ้น Cloudflare
- **เพิ่มหน้าข้อตกลงและความเป็นส่วนตัว** และชุดทดสอบใน `tests/`
- **service worker** ไม่ยุ่งกับคำขอข้ามโดเมนอีกต่อไป

### 2026-10-06 — แก้ผลตรวจความปลอดภัย
- **แก้ช่องโหว่:** ไฟล์สำรองที่ถูกดัดแปลงเคยฝังสคริปต์ลงหน้าแอปได้ผ่านช่องจำนวนคนและจำนวนวัน ตอนนี้ข้อมูลจากไฟล์นำเข้าและ `localStorage` ผ่าน `normalize()` ที่ตรวจชนิดและรูปแบบทุกช่องก่อนใช้
